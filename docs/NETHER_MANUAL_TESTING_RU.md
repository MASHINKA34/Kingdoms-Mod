# Ручная проверка Ада Kingdoms

Инструкция рассчитана на отдельный тестовый мир с актуальным jar Kingdoms. Для проверки фракционных сценариев нужны как минимум оператор и два обычных клиента; для одновременного сравнения первой и второй сессий удобнее три обычных клиента.

Перед проверкой wipe сделайте резервную копию мира. Запланированный wipe физически удалит данные Ада при следующем безопасном запуске сервера.

## 1. Подготовка

1. Установите `build/libs/kingdoms-0.2.11.jar` вместе с обязательными зависимостями сервера.
2. Запустите сервер и выдайте одному тестовому аккаунту права оператора из консоли:

   ```text
   op Admin
   ```

3. Войдите как `Admin`, встаньте в точке общего спавна и при необходимости задайте её:

   ```text
   /setworldspawn ~ ~ ~
   /kingdoms dimension nether open
   /kingdoms dimension nether status
   /kingdoms dimension nether portal status
   ```

   `open` снимает только административную блокировку. Реальное ежедневное окно всё равно остаётся 18:00–23:00 Europe/Moscow.

4. Создайте тестовые фракции обычными игровыми командами. Например, игрок `Alpha1`:

   ```text
   /f create Alpha
   /f invite Alpha2
   ```

   Игрок `Alpha2` принимает приглашение:

   ```text
   /f join Alpha
   ```

   Игрок `Beta1` отдельно создаёт вторую фракцию:

   ```text
   /f create Beta
   ```

## 2. Основной портал на спавне

1. Оператор строит обычную обсидиановую рамку не дальше 64 блоков от общего спавна и зажигает её огнивом.
2. Убедитесь, что оператор получил сообщение об автоматической регистрации.
3. Проверьте сохранённые границы:

   ```text
   /kingdoms dimension nether portal status
   ```

4. Перезапустите сервер и повторите `portal status`: регистрация должна сохраниться.
5. Постройте вторую допустимую рамку рядом со спавном и зажгите её оператором. Она должна заменить регистрацию первой. Обычный игрок не должен войти через старую рамку.
6. Диагностическое удаление регистрации выполняется командой:

   ```text
   /kingdoms dimension nether portal clear
   ```

   После этого ни одна старая рамка не должна пускать обычного игрока. Зажгите основной портал оператором заново для следующих проверок.

### Запрет пользовательских порталов

1. Снимите права оператора с отдельного проверочного игрока.
2. Дайте ему обсидиановую рамку и огниво в любом месте, включая район спавна.
3. При попытке зажечь рамку огонь/портал не должен появиться; сообщение должно быть: «Портал в Ад находится на спавне».
4. Портал, созданный командой, раздатчиком или другим незарегистрированным способом, также не должен давать обычному игроку доступ.

## 3. HUD и расписание

Принудительные предпросмотры доступны только оператору и не меняют расписание, сессии или серверные данные:

```text
/kingdoms dimension nether hud test opening 300
/kingdoms dimension nether hud test open 300
/kingdoms dimension nether hud clear
```

Проверьте оба режима на нескольких разрешениях, GUI Scale `Auto`, `2`, `3`, `4` и на русском языке. Панель должна помещаться справа, переносить длинный текст и обновлять счётчики без повторного открытия GUI.

Для проверки реального времени используйте тестовый сервер в московском окне; часы берутся с сервера, а не с клиента:

- 17:54:59 — панели нет;
- 17:55:00 — появляется обратный отсчёт `5:00`;
- 18:00:00 — вход разрешён, панель остаётся и показывает закрытие/сессии;
- 21:45 — новая сессия разрешена и заканчивается в 23:00 через 75 минут;
- 22:50 — новая сессия разрешена и заканчивается через 10 минут;
- 23:00:00 — вход закрыт, HUD исчезает, обычные игроки безопасно возвращаются в Overworld.

Не меняйте системные часы рабочего сервера. Границы 18:00/23:00 и сокращение поздней сессии дополнительно закреплены unit-тестами.

## 4. Инвентарь и камень возвращения

До первого успешного входа заполните у `Alpha1` основной инвентарь и центральный слот hotbar. Центральный слот в команде — `hotbar.4`, основной инвентарь — `inventory.0` … `inventory.26`:

```text
/item replace entity Alpha1 hotbar.4 with minecraft:diamond
/item replace entity Alpha1 inventory.0 with minecraft:cobblestone 64
```

Повторите последнюю команду для `inventory.1` … `inventory.26`. При входе должны выполниться все условия:

- телепортации нет;
- алмаз не исчезает;
- показано сообщение «Освободите центральную ячейку панели быстрого доступа, чтобы войти в Ад»;
- HUD по-прежнему показывает `2/2`, то есть сессия не потрачена.

Освободите одну основную ячейку и войдите снова:

```text
/item replace entity Alpha1 inventory.0 with minecraft:air
```

Алмаз должен безопасно перейти в освободившуюся ячейку, а привязанный камень появиться строго в пятом слоте hotbar.

В режиме survival последовательно попробуйте переместить выданный камень:

- клавишей `Q` и выбрасыванием из инвентаря;
- клавишами цифр и `F` в offhand;
- обычным кликом, Shift-кликом, swap и drag;
- через cursor stack;
- в сундук, crafting grid и другой открытый контейнер.

Сервер должен вернуть камень в `hotbar.4` максимум примерно за секунду, а заменённый предмет — вернуть в исходное место/контейнер без потери. Дубликат привязанного камня не должен сохраняться. Обычная непривязанная creative-копия `kingdoms:nether_return` такими правилами не фиксируется.

Зажмите ПКМ с привязанным камнем на 2 секунды. Игрок должен оказаться в безопасной позиции около зарегистрированного портала в Overworld; камень и boss bar должны исчезнуть, но сессия остальных участников продолжиться.

## 5. Точки фракций и общий вход участников

1. В реальном открытом окне сначала войдите `Alpha1`, затем — `Alpha2`.
2. Пока `Alpha1` остаётся в Аду, `Alpha2` должен появиться в безопасной позиции рядом с ним, а не у отдельного ванильного портала.
3. Войдите `Beta1` из другой фракции. Его точка должна быть другой и заметно удалённой от точки Alpha (минимум задаётся `landingMinimumSeparation`, по умолчанию 512 блоков).
4. Осмотрите обе точки: под ногами твёрдый блок, достаточно воздуха, нет лавы, стены, пустоты и крыши Ада; портал назначения не создаётся.
5. Перезайдите участником активной сессии: должна использоваться сохранённая точка/позиция рядом с участником той же сессии.

## 6. Две сессии, смерть и разные таймеры

1. `Alpha1` и `Alpha2` входят в общую первую сессию. HUD должен показать одну израсходованную сессию, оба игрока получают один и тот же таймер первой сессии.
2. Убейте `Alpha2` в Аду. Камень не должен выпасть, а повторный вход в ту же сессию должен быть заблокирован только для него.
3. Через некоторое время `Alpha2` касается основного портала. Первое касание не расходует вторую сессию и показывает предупреждение:

   ```text
   Если вы войдёте сейчас, будет начата вторая сессия вашей фракции. Продолжить?
   ```

4. Отойдите от портала и в течение 15 секунд войдите снова, удерживая Shift. Только теперь стартует вторая сессия.
5. Сравните экраны: `Alpha1` остаётся в первой сессии со старым boss bar, `Alpha2` видит отдельный более поздний таймер второй сессии. Запуск второй сессии не переносит и не выкидывает `Alpha1`.
6. `Alpha1` выходит камнем и входит снова: теперь он присоединяется к активной второй сессии и получает её boss bar.
7. Повторная смерть `Alpha2` во второй сессии или попытка третьего запуска должна дать понятный отказ до следующего московского дня.
8. Для быстрой проверки раздельного окончания на одноразовом стенде можно временно поставить `netherSessions.sessionDurationMinutes = 2` в `kingdoms-server.toml`, перезапустить сервер, выполнить сценарий и затем обязательно вернуть значение `90`. Окончание первой сессии должно эвакуировать только закреплённых за первой; вторая продолжает работать до собственного дедлайна.

### Reconnect и restart

1. Отключите клиента, пока игрок находится в активной сессии, затем подключитесь снова. Привязанный камень и правильный boss bar должны восстановиться.
2. Перезапустите сервер до истечения сессии. Абсолютный дедлайн не сдвигается на время простоя; принадлежность игроков к первой/второй сессии и разные таймеры сохраняются.

## 7. Принудительный возврат и закрытие в 23:00

Для немедленной эксплуатационной проверки оператор выполняет:

```text
/kingdoms dimension nether close
```

Все обычные игроки в Аду должны безопасно вернуться к зарегистрированному spawn-порталу; boss bars и привязанные камни удаляются. Затем административную блокировку можно снять:

```text
/kingdoms dimension nether open
```

Команда не открывает доступ вне ежедневного окна. Такое же безопасное завершение всех параллельных сессий должно происходить автоматически ровно в 23:00 Europe/Moscow.

## 8. Creative-вкладка

Откройте creative-вкладку Kingdoms и проверьте предметы/BlockItem всех зарегистрированных блоков, в частности:

- `kingdoms:nether_return`;
- `kingdoms:outpost_core`;
- четыре ресурсных кластера.

Creative-копия камня без серверного data component не должна принудительно занимать центральный слот.

## 9. Только ручной Nether-wipe

1. Обычный restart без действий ключом не должен создавать pending wipe. Запомните участок Ада, перезапустите сервер и убедитесь, что участок остался неизменным.
2. Убедитесь, что команды `/kingdoms dimension nether wipe` не существует; read-only статус остаётся доступен:

   ```text
   /kingdoms dimension nether status
   ```

3. Оператор получает и использует ключ:

   ```text
   /give Admin kingdoms:dimension_key
   ```

4. В секции Ада нажмите «Вайп при рестарте», затем отдельную кнопку подтверждения. UI должен показать `Вайп при рестарте: запланирован`.
5. До рестарта нажмите «Отменить вайп», затем подтвердите отмену. Закройте и снова откройте ключ: pending-флага нет. Перезапуск не удаляет Ад.
6. Запланируйте wipe ключом ещё раз и штатно остановите сервер. На следующем безопасном запуске данные Ада удаляются один раз, pending-флаг снимается, мир Ада создаётся заново.
7. Выполните ещё один restart без нового подтверждения: повторного wipe быть не должно.

Сетевой запрос привязан к игроку и одноразовой UI-сессии, проверяет права оператора, ограничивается по частоте и не принимается повторно после успешного действия.

## 10. Автоматическая проверка перед выдачей jar

Из корня репозитория:

```powershell
.\gradlew.bat test
.\gradlew.bat runGameTestServer
.\gradlew.bat build
```

Готовый серверный артефакт: `build/libs/kingdoms-0.2.11.jar`.
